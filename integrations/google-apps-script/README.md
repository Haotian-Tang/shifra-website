# SHIFRA registration intake

The public website can be hosted on GitHub Pages or Netlify. This owner-deployed Apps Script web app receives registrations without requiring visitors to sign into Google. It does not expose a participant list or return private Drive links to visitors.

Install `Code.gs`, `Registration.html`, and `appsscript.json` in a standalone Apps Script project. Replace the two placeholders in `REGISTRATION_STORE` with the private registration spreadsheet and submission-folder IDs. Keep these configured IDs in Apps Script rather than this public repository. The spreadsheet must have a `Registrations` tab with the 21 headers used by the intake. Preserve existing columns A:M, and append N:Q as `First name`, `Last name`, `Gender`, and `Title`; then R:U as `Consider for 10-min talk`, `Recording consent`, `Consent recorded at (UAE)`, and `Consent wording version`. The spreadsheet time zone is Asia/Dubai.

The parent submission folder must have limited access enabled and General access set to Restricted. Place the spreadsheet inside it. Do not inherit public link permissions from the publicity folder. Add specific organisers only when the owner authorises their access.

Deploy as the owner with access set to **Anyone**. Google requires the owner to authorise Drive and Sheets access. These Google scopes allow account-wide file and spreadsheet access; the implementation limits its operations to the two configured destinations. It does not delete files, list unrelated files, send email, or publish submissions.

Set the returned production `/exec` URL in `src/data/registration.ts`. The build verifier prevents publishing a missing URL or the disconnected local form preview. Re-deploy a new Apps Script version whenever its source changes; updating repository code alone does not update the live receiver.

Audience registrations require first name, last name, gender, email, affiliation, and recording consent. Gender includes a Prefer not to say option. Honorific title remains optional. The combined name remains in column C for compatibility, with the new fields stored in N:Q and `registration.json`. Existing records and consent are never backfilled or changed by these updates. Abstract registrations additionally require an abstract title and an explicit choice of Text or Upload your abstract. The selected input is mandatory; the other is disabled in the form and ignored by the server. Text submissions save only abstract text; uploads save only a PDF/Word/text attachment. The selected `abstractMethod` is stored in `registration.json` without adding a spreadsheet column. Attachments are limited to 10 MB; abstract text is limited to 30,000 characters. Each registration creates a private folder with `registration.json`, optional `abstract.txt`, and an optional attachment. The sheet stores the matching links and a review status. It does not claim abstract acceptance or send confirmation email.

The client retains one request ID across retries. A script lock and stored request IDs prevent duplicate rows. Success appears only after Drive files are saved and the row is flushed to Sheets. All administrative helpers are private to the script; the public RPC accepts registration input and returns only a reference and participation type. User-entered text is escaped before being written to Sheets.

Abstracts close after 11:59 PM UAE time on Tuesday, 24 November 2026. The server cutoff is `2026-11-25T00:00:00+04:00`; audience registration remains open. A previously saved request can still retrieve its success receipt after the cutoff without creating a duplicate. The form displays the deadline without depending on the visitor’s device clock.

New forms identify themselves with `formVersion=5`. Only current forms can create new records: stale v4 and legacy forms receive an instruction to reload. The server looks up an existing request ID first so a previously saved registration can still retrieve its original receipt without changing its original information or consent. Input validation, including the current version, mandatory gender, recording consent, abstract title, and selected method, happens before any Drive files or Sheet rows are written.

Abstract submitters must explicitly answer Yes or No to consideration as a Selected Speaker for a 10-minute presentation; neither option is preselected. This records interest only and does not imply acceptance. Column R is `Yes`/`No` for abstract registrations or `Not applicable` for audience registrations. Older `Not provided` records remain unchanged.

Recording consent is required and checked by default in v5. Unchecking it blocks submission, and the server requires the checkbox value `yes`. New records store `Yes` in column S, the server receipt timestamp in T (displayed in UAE time), and the unchanged wording version `recording-v1` in U. The private `registration.json` stores the full wording, timestamp, `formVersion`, `consentRequired: true`, and `consentDefaultChecked: true` to distinguish the v5 interaction from earlier versions that used an optional, unchecked checkbox. A retry returns the original receipt without modifying the original consent record. Do not alter or infer consent for existing records.
